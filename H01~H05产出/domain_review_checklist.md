# Tilt · 领域库人工评审清单（`docs/domain_review_checklist.md`）

> 用途：脚本（`tools/validate_domains.py`）只管得住"格式与冻结值"，管不住"内容质量"。
> 本清单给人工评审用，覆盖 7 个维度，每条给出「看什么 / 什么样算不合格 / 举例」。
> 使用方式：打印或复制到 checklist 工具，逐条勾选 `- [ ]` → `- [x]`。
> 适用范围：C01 产出的 50 个领域库（`domains.csv` 及按领域拆分的 `{domain_id}.yaml`）。

## 0. 评审前置动作（先做这三步，再进入维度）

- [ ] 先跑脚本并确认 10 项检查全 PASS：`python3 tools/validate_domains.py --ssot ssot/domains.csv --input out/domains.csv`
- [ ] 确认脚本报告里 `合计：错误 0 / 警告 0`；有 ERROR 时**先修格式再评审内容**，否则会重复劳动
- [ ] 确认手上这份产出的 `baseline_version` 与本次评审批次一致（不同批次不要混在一张清单上勾）

---

## 1. 描述准确性

- [ ] **看什么**：`description` 是否准确反映这个领域本身（工具有哪些、活动形态是什么、典型产出是什么），且能让人一眼认出是这个领域而不是别的。
  - **不合格**：张冠李戴；写成相邻/上位领域；空泛到可以套在任意领域上（"提升自我""锻炼思维"）。
  - **举例**：✗ `astronomy` 描述成"观测天气与气候变化规律" → 那是 `meteorology`；✗ `reading` 描述成"获取知识提升认知" → 空泛到可套任何领域。
- [ ] **看什么**：`name`（中文名）与 `id` 是否对得上，中英文语义是否一致。
  - **不合格**：`id=script_writing` 但中文名写成"文案写作"；`id=modeling_3d` 但中文名写"建模"而描述讲的是数学建模。
  - **举例**：✗ `bridge`（桥牌）描述里出现"叫牌定约"之外的"输墩计算"以外的桥牌术语错位，或写成"扑克类游戏"这种含糊上位词。
- [ ] **看什么**：`description` 是否混入 SPEC 之外的产品承诺（就业、收入、天赋保证）。
  - **不合格**：出现"学完可接单""月入过万""一定能成为"一类表述。
  - **举例**：✗ `ui_design` 描述含"4 周可接单变现" → 越界，违反产品明确不做的事。

## 2. 判定性语言

- [ ] **看什么**：`name` / `category` / `description` 是否出现对用户下结论的表述（违反 SPEC 8.2、硬约束 5）。
  - **不合格**：出现"适合 XX 型的人""需要有天赋""你不适合""你一定有"这类判定句；判断权没有交回用户本人。
  - **举例**：✗ "适合内向、喜欢独处的人"；✓ 改为"更常被偏好独处的学习者选择，是否适合由你自己判断"。
- [ ] **看什么**：是否对该领域的"人群标签"做了绝对化归因。
  - **不合格**："天生/骨子里/一定/肯定 + 有/适合/擅长"结构。
  - **举例**：✗ "你天生适合音乐类领域"；✗ "你肯定有写作天赋"。
- [ ] **看什么**：`why_recommended` 类文案（若存在）是否把"推荐"写成了"判定"。
  - **不合格**：写成系统替用户做了决定的口吻（"你应该选这个领域"）。
  - **举例**：✗ "建议优先选择该领域"；✓ 改为"可作为候选之一，与其余候选一起用 4 周斜率对比后再决定"。

## 3. 学习路径合理性

- [ ] **看什么**：`typical_learning_path` 四段（L1-L2 / L2-L3 / L3-L4 / L4-L5）的小时区间是否连贯、是否单调递进、是否落在 4 周 × 每天 15-30 分钟可承受的量级内。
  - **不合格**：区间断裂或倒退（第 3 段比第 2 段还少）、单段时长离谱、"X 小时精通"式承诺。
  - **举例**：✗ "10 小时精通围棋"；✗ 四段写成 `2-4 / 6-10 / 3-5 / 20-30`（第 3 段倒退）。
- [ ] **看什么**：每段描述的活动是否与该 Level 语义匹配（L1 纯学习无产出压力、L2-L3 基础操作有明确产出、L4-L5 中级产出可被评估）。
  - **不合格**：L1 就要求"完成一件可评估作品"；L4-L5 还停在"看教程"。
  - **举例**：✗ `programming` 的 L1 写"独立写出一个可运行的小游戏" → 那是 L3 以上。
- [ ] **看什么**：是否存在跨领域复制粘贴的雷同路径（换了个领域名，四段内容几乎一样）。
  - **不合格**：两个 Gardner 分类完全不同的领域，学习路径逐句相同。
  - **举例**：✗ `yoga` 与 `cryptography` 的 L2-L3 段落文字高度重合 → 典型的批量生成痕迹，需重写。

> 注：`typical_learning_path` 字段不在 `domains.csv` 的 13 列契约内，若它位于 YAML/其他文件中，请按领域 ID 对照本条评审（见文末备注）。

## 4. 成本合理性

- [ ] **看什么**：`estimated_cost_per_month` 是否落在该领域常识区间内（器材/场地/课程/订阅等）。
  - **不合格**：明显偏离常识，高到不像入门 4 周的量级，或低到无法成立。
  - **举例**：✗ `go`（围棋）写 2000 元/月（入门以线上对弈为主，常识应在百元级）；✗ `piano`（钢琴）写 0 元/月（琴房/键盘设备成本无法为零）。
- [ ] **看什么**：成本是否与 `startup_difficulty`（SSOT 冻结值）方向一致。
  - **不合格**：启动成本低的领域却标了高月成本，或启动成本高的领域月成本为 0，且描述中没有解释。
  - **举例**：✗ `running`（长跑，启动成本 2）写 800 元/月且无说明。
- [ ] **看什么**：成本口径是否统一（是否含器材摊销、是否含课程费），同一批产出里不能两种口径混用。
  - **不合格**：部分领域按"含器材一次性投入摊销"、部分按"纯月费"。
  - **举例**：✗ `photography` 含机身摊销、`video_editing` 只算软件订阅，两者不可比。

## 5. 门槛一致性

- [ ] **看什么**：`pain_tolerance_required`（1-5）与该领域"早期枯燥/挫败程度"是否匹配。
  - **不合格**：明显不匹配——枯燥且进步慢的领域标 1，反馈极快的领域标 5。
  - **举例**：✗ `philosophy`（反馈速度 1）标 1；✗ `djing`（反馈速度 5）标 5。
- [ ] **看什么**：与 SSOT 冻结的 `feedback_speed` / `startup_difficulty` 是否方向一致（反馈慢 + 启动难 → 门槛应偏高）。
  - **不合格**：反馈慢、启动难的领域却标了低门槛，且描述里没给理由。
  - **举例**：✗ `math_olympiad`（启动 4 / 反馈 2）标 2。
- [ ] **看什么**：同一 Gardner 分类内，门槛值是否呈现合理梯度，而不是清一色同一数字。
  - **不合格**：某一分类下 7 个领域全部写 3，看起来像批量默认值。
  - **举例**：✗ linguistic 七项全为 3 → 需逐项复核是否真的一致。

## 6. 分类一致性

- [ ] **看什么**：同一 `gardner_intelligence` 下的 `category` 命名风格是否统一（同为"名词短语"、同为"动作/学科名"、粒度是否一致）。
  - **不合格**：同一分类里混用"学科名"与"活动名"与"职业名"三种粒度。
  - **举例**：✗ musical 下同时出现"音乐"（学科）、"演奏活动"（活动）、"音乐人"（职业）→ 需统一到一种。
- [ ] **看什么**：多值 `gardner_intelligence`（`;` 分隔）是否有依据，主分类是否放在首位。
  - **不合格**：挂了三四个智能、主次不分，明显是"沾边就加"。
  - **举例**：✗ `sales` 写成 `interpersonal;musical;naturalist`。
- [ ] **看什么**：`category` 是否出现了 SSOT 之外的自造分类词，或与 Gardner 中文名冲突。
  - **不合格**：出现冻结清单外的分类标签；或 `gardner_intelligence=spatial` 但 `category` 写"语言类"。
  - **举例**：✗ `astronomy` 的 category 写"自然科学"而 naturalist 下其他项都写"自然观察类" → 风格不一致。

## 7. 跨领域矛盾

- [ ] **看什么**：有没有两个领域的 `description` 互相打架（同一个术语在两处定义相反、同一能力被两个领域各自声称独占）。
  - **不合格**：A 说"需要极强空间想象"，B 说"不需要任何空间能力"，而两者同属 spatial。
  - **举例**：✗ `painting` 写"不需要素描基础"而 `modeling_3d` 写"必须有美术与素描基础"，且两者共享入门路径。
- [ ] **看什么**：相邻/易混领域（`go` vs `chess` vs `bridge` vs `strategy_games`；`writing_general` vs `blogging` vs `biography_writing`；`psychology` vs `counseling` vs `coaching`）边界是否清晰、是否有重复描述。
  - **不合格**：两处描述大面积重复，或边界靠"程度词"区分（"稍微更偏…"）。
  - **举例**：✗ `coaching` 与 `counseling` 描述都写"帮助他人解决问题" → 必须给出可区分的产出差异。
- [ ] **看什么**：跨领域数值是否自相矛盾（如 A 的入门时间远长于明显更难理解的 B）。
  - **不合格**：`estimated_time_to_proficiency` 的排序与 `startup_difficulty`（冻结值）的排序明显冲突。
  - **举例**：✗ `programming`（启动 4）写"20 小时上手"而 `blogging`（启动 2）写"200 小时上手"。

## 8. 抽样策略建议

- [ ] **每批抽检 20%**：每批产出随机抽 20% 的领域，走完上面 7 个维度全项。
- [ ] **高危领域 100% 全检**（满足任一条件即列高危，基于第 3.1 冻结表的数值推导）：
  - 启动成本 ≥ 4 且 反馈速度 ≤ 2：`philosophy` `math_olympiad` `cryptography` `counseling` `psychology` `architecture_design` `animation`
  - `gardner_intelligence` 为多值（`;` 分隔）的条目：易出现主次不分
  - `verify_status` 为 `待核验` 的条目：事实性内容未坐实
  - 批次拼接交界处的条目（每批首尾各 2 个）：拼接最容易丢行/错行
- [ ] **易混领域成对评审**：上表第 7 维度的易混组必须成对看，不允许只勾其中一个。
- [ ] **两次评审间隔**：同一批产出由两名评审各抽 20%（不重叠），高危领域两人都要看。
- [ ] **评审结论记录**：不合格条目按 `领域 ID · 维度编号 · 问题描述 · 建议改法` 四段记录，回写给出产方；不改冻结数值，只改非冻结内容。
