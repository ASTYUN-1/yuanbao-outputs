# Tilt 前端改造检查清单（H02）

> 用途：4 个原型页（`01_questionnaire.html` / `02_report.html` / `03_dailytask.html` / `04_domains.html`）完成接口对接改造后，逐项验收。
> 用法：每条给出「检查方法（怎么测）」与「合格标准」，验收时逐条勾选；未通过项记录实际表现并回到 `docs/api_contract.md` 核对字段。
> 默认验收视口：**移动端 375px 为主**，兼顾 414 / 768。

---

## A · 响应式（移动端 375px 为主，兼顾 414 / 768）

- [ ] **A1 · viewport 设置正确**
  - 检查方法：查看每个 HTML 的 `<head>` 是否含 `<meta name="viewport" content="width=device-width, initial-scale=1">`
  - 合格标准：存在该标签；未使用 `user-scalable=no` 或 `maximum-scale=1` 禁用缩放

- [ ] **A2 · 375px 下无横向滚动**
  - 检查方法：DevTools 设备模拟 375×667，横向滑动页面；控制台执行 `document.documentElement.scrollWidth`
  - 合格标准：`scrollWidth ≤ 375`，页面不出现横向滚动条，无元素被推出视口

- [ ] **A3 · 触摸目标 ≥ 44×44px**
  - 检查方法：DevTools 逐一检查可点击元素（选项、按钮、任务卡片、领域卡片、打卡按钮）的盒模型尺寸
  - 合格标准：交互元素实际可点区域 ≥ 44×44 CSS px；相邻可点元素间距 ≥ 8px

- [ ] **A4 · 文字不溢出、不被裁切**
  - 检查方法：375px 下逐屏检查长题目、长领域名、长文案、任务标题的换行与省略表现
  - 合格标准：无文字被容器裁切或溢出；长文本自动换行，超长时以省略号收尾且内容可通过交互查看

- [ ] **A5 · 414 / 768 兼容不破版**
  - 检查方法：分别在 414×896 与 768×1024 下加载 4 个页面
  - 合格标准：布局不破版、无元素重叠；768 下容器居中且两侧留白合理

- [ ] **A6 · 图表（雷达图 / 折线图）自适应**
  - 检查方法：375px 下查看问卷末屏 6 维雷达、报告页水平曲线与 5 维雷达
  - 合格标准：画布不溢出、不被压扁变形；轴上文字 ≥ 10px 可读；Canvas 设置 `responsive: true` 且 `maintainAspectRatio` 按设计设定

- [ ] **A7 · 安全区域适配（刘海屏 / 底部横条）**
  - 检查方法：在带安全区的设备上（或 DevTools 模拟）检查顶部与底部是否被遮挡
  - 合格标准：使用 `env(safe-area-inset-*)` 留出安全边距，关键按钮不被系统横条遮挡

## B · 无障碍

- [ ] **B1 · 图片与图标有替代文本**
  - 检查方法：检查所有 `<img>` 是否带 `alt`；纯装饰性图标是否 `aria-hidden="true"`
  - 合格标准：承载信息的图有描述性 `alt`；纯装饰图标 `aria-hidden="true"`；无空 `alt` 承载信息的情况

- [ ] **B2 · 表单与选项有可访问名称**
  - 检查方法：检查每个输入控件、单选项、自定义选项卡片是否有关联 `<label>` 或 `aria-label`
  - 合格标准：所有可聚焦控件都有屏幕阅读器可朗读的可访问名称；分组有 `fieldset` / `legend` 或等效语义

- [ ] **B3 · 颜色对比度达标**
  - 检查方法：用 DevTools 或对比度工具检查正文与背景、按钮文字与底色、图表轴文字与底色
  - 合格标准：正文文本对比度 ≥ 4.5:1；大号文字与图形元素 ≥ 3:1；深色背景下单一强调色仍满足要求

- [ ] **B4 · 键盘可完整操作**
  - 检查方法：仅用 Tab / Shift+Tab / Enter / Space 完成问卷作答、任务打卡、领域筛选全流程
  - 合格标准：所有交互可键盘完成；焦点顺序符合视觉顺序；焦点样式清晰可见（未被 `outline: none` 抹掉）

- [ ] **B5 · 雷达图有文字替代**
  - 检查方法：检查问卷末屏 6 维雷达、报告页 5 维雷达是否配有数据表格或文字摘要
  - 合格标准：每个雷达图配一份文字替代（表格或要点列表），覆盖全部轴名与取值；坐标轴含义有中文说明

- [ ] **B6 · 状态不只靠颜色传达**
  - 检查方法：检查进度条、任务完成态、筛选选中态是否仅用颜色区分
  - 合格标准：状态同时有文字标签或图标辅助；色盲用户可区分

- [ ] **B7 · 动态区域可被感知**
  - 检查方法：检查加载完成、打卡成功、上报失败等动态变化是否有 `aria-live` 或等效提示
  - 合格标准：动态结果有可感知提示；错误提示文案引导性、不含判定性表述

## C · 性能

- [ ] **C1 · 首屏渲染时间**
  - 检查方法：DevTools Performance / Network，375px + Fast 3G（或 4G）节流下测 FCP / LCP
  - 合格标准：首屏关键内容可见 FCP ≤ 2.5s、LCP ≤ 2.5s（**待定**：与需求方确认基线指标）

- [ ] **C2 · Chart.js 按需加载**
  - 检查方法：检查 Chart.js 是否仅在实际需要图表的页面 / 时机加载（动态 `import()` 或 `defer`），且走 CDN
  - 合格标准：无图表的页面不请求 Chart.js；图表脚本异步加载，不阻塞首屏渲染；符合 4.4 单文件无构建、第三方库走 CDN 的约束

- [ ] **C3 · localStorage 容量可控**
  - 检查方法：检查问卷答案、领域缓存、事件队列的写入量；模拟多日累计后读取 `localStorage` 占用
  - 合格标准：单用户占用远低于 5MB 上限（建议 < 1MB）；超限时能清理旧数据或降级，不抛异常

- [ ] **C4 · 离线降级可用**
  - 检查方法：断网后打开 4 个页面，检查已缓存数据能否展示
  - 合格标准：已缓存的题目、领域、任务列表可展示；页面给出"当前离线"提示；不白屏、不抛未捕获错误

- [ ] **C5 · 50 个领域卡片渲染流畅**
  - 检查方法：页面 04 渲染 50 张卡片，用 Performance 面板录制滚动过程看帧率
  - 合格标准：滚动无明显卡顿（帧率稳定）；必要时改用懒加载或虚拟列表

- [ ] **C6 · 静态资源体积受控**
  - 检查方法：Network 面板统计各页总传输体积与大文件
  - 合格标准：单页总传输体积在可接受范围；无 > 200KB 的非必要图片资源（**待定**：确认原型是否含图片资源）

## D · 接口对接

- [ ] **D1 · 加载态 / 空态 / 错误态三态齐全**
  - 检查方法：对每个数据区域（题目、报告、今日任务、领域列表）分别模拟：正常返回、返回空数组、接口返回 500
  - 合格标准：三种状态各有对应 UI（骨架屏或加载提示 / 空态引导文案 / 错误提示）；无空白区块、无卡死在加载中

- [ ] **D2 · 请求失败可重试**
  - 检查方法：断网发起请求后，在错误态点击"重试"；恢复网络再点一次
  - 合格标准：错误态提供重试入口；点击后能重新发起请求并在恢复后成功渲染；重试不限死次数

- [ ] **D3 · 上报失败本地缓存待重发**
  - 检查方法：断网时触发 `task_start` / `task_pause` / `task_resume` / `task_complete` 上报，随后恢复网络
  - 合格标准：失败事件写入本地队列并持久化；联网后自动重发；按 `task_id + event_type + timestamp` 幂等处理，不丢失、不重复

- [ ] **D4 · 鉴权失效处理**
  - 检查方法：用过期或无效 token 发起请求
  - 合格标准：收到 `401 UNAUTHORIZED` 后引导重新获取登录态；不向用户暴露报错详情或 token 信息

- [ ] **D5 · 字段与冻结清单对齐**
  - 检查方法：拿真实响应逐字段比对 `docs/api_contract.md` 与第 3 节冻结清单
  - 合格标准：`domain` 全部命中 3.1 的 50 个 ID 白名单；`coordinate` 六维取值在 3.4 枚举内；指标名为 3.5 的 5 个固定字段名；`event_type` 在 3.6 的 12 个枚举内；`task_id` 符合 3.7 规范

- [ ] **D6 · 埋点事件序列完整**
  - 检查方法：完整走一次任务流程（开始 → 暂停 → 继续 → 完成），在 Network 面板检查上报序列与请求体
  - 合格标准：事件序列为 `task_start` →（`task_pause` / `task_resume`）× N → `task_complete`；请求体字段与 SPEC 4.2 schema 一致（含 `duration_seconds` / `pause_count` / `pause_durations` / `completion_rate` / `objective_score` / `success`）；不适用字段为 `null` 而非缺失

- [ ] **D7 · 领域数值与坐标系字段未混淆**
  - 检查方法：检查 `/domains` 响应中的 `feedback_speed`（1-5 数值）与 `coordinate.feedback_speed`（`short` / `long` 枚举）的解析逻辑
  - 合格标准：两者走各自独立的解析与渲染逻辑；未复用同一份取值映射；雷达图渲染不因该字段产生错误

- [ ] **D8 · 面向用户的文案保持引导性**
  - 检查方法：通读所有由接口返回或前端渲染的用户可见文案（空态、错误提示、领域说明、报告结论）
  - 合格标准：无"你擅长 X"/"你不适合 Y"/"你是 Z 型人"等判定性表述；判断权交回用户本人；仅呈现斜率与信号

- [ ] **D9 · 领域选择结果落库**
  - 检查方法：在页面 04 筛出 3-5 个领域并确认，检查 `POST /api/v1/user_domains` 请求与后续页面 03 的任务生成
  - 合格标准：选中结果成功保存；页面 03 能基于已保存领域生成今日任务；选择数量不足 3 或超过 5 时前端先拦截并给出引导提示
